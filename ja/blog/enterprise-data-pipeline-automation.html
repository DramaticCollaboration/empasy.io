セキュリティ基準を守りながら非定型業務データを自動整理した導入事例

経営層・現場担当者のための3行要約
  • 従来の課題社内に分散したPDF・掲示板・公開資料を手作業で分類し、個人情報を伏せて整理するには大きな工数と漏えいリスクが伴います。
  • 解決アプローチ索引化前の段階で機密個人情報を自動マスキングし、不要要素を除いた構造化テキストをハイブリッド検索基盤へ格納します。
  • 導入効果閉域環境や部門別権限を守りながら、社内検索の精度とレポート作成スピードを両立できます。

金融・公共・製造などセキュリティ要件の厳しい現場では、規程PDF、議事録、社内掲示板、外部の法令・市場資料といった非定型業務データが日々蓄積されています。しかし、生データをそのまま検索基盤やAIに投入すると、個人情報（PII）の露出やノイズ混入による誤回答が導入の障壁になります。

Empasyでは、SyncCrawl、SyncLLM、sync-module-rag、SyncInsightを連携させ、社内セキュリティ境界内で安全に構造化を行う5層データ整理パイプラインを構成しています。

1. 非定型データ活用で直面する3つの課題

  • 本文中の個人情報混在：問い合わせ履歴や報告書に氏名・電話番号・口座番号・メールアドレスが含まれており、そのまま索引化すると規程違反リスクが生じます。
  • ノイズによる検索精度低下：Webページの広告やナビゲーション、PDFのヘッダー・フッターが混ざると、重要な表や数値の文脈が失われます。
  • 閲覧権限の未分離と版管理不足：部門ごとの閲覧権限を考慮せずに一括格納すると、閲覧制限文書や改定前の旧規程が検索結果に混在してしまいます。

2. 5-Layer セキュリティ重視データ整理パイプライン

収集から検索までの全工程に検証・マスキング・監査履歴を組み込んでいます。

LAYER 01
安全な収集と差分検知
SyncCrawlがrobots.txtを遵守して公開Web・社内文書を収集し、ハッシュ比較で更新分のみ抽出
LAYER 02
8種個人情報(PII)の自動マスク
電話番号・口座番号・メール・識別番号などの機密パターンを索引化前に自動検知・置換
LAYER 03
ノイズ除去と構造化
広告・メニュー・繰り返しヘッダーを除去し、見出し・表・箇条書きを保持したMarkdown/JSONへ変換
LAYER 04
3重ハイブリッドRAG索引
sync-module-ragが意味単位で分割し、PostgreSQL 18.6 pgvector + BM25 + ナレッジグラフへ登録
LAYER 05
権限制御付き検索・監査
部門・役職RBACフィルタと監査ログのもとでSyncInsightが根拠付き回答・レポートを生成

3. 個人情報保護と閉域環境での設計原則

  • 索引化前の先制マスキング：埋め込みモデルやLLMへ渡す前段階で識別子を安全トークン（例：[MASKED_PHONE]）へ置換します。
  • 閉域・オンプレミス完結：ローカルLLMランタイム（vLLM、Ollama）とPostgreSQL 18.6 pgvectorにより、外部通信なしで全工程を運用できます。
  • メタデータによる権限制御と出典提示：各チャンクに部門権限・版番号・原本リンクを付与し、許可された利用者のみへ最新根拠を提示します。

4. 段階的導入のポイント

  • 手作業の分類・伏字工数を削減：重複排除とマスキングを自動化することで、担当者は例外確認と最終判断に注力できます。
  • スモールスタートでの品質検証：まずは社内規程集や公開法令など利用頻度の高い1〜2領域で1〜2週間のパイロットを行い、マスキング精度と検索結果を確認したうえで全社展開する進め方を推奨しています。
分散した社内文書を安全な検索資産へ変えませんか SyncCrawl・SyncLLM・SyncInsightが社内環境で非定型データを整理・活用する仕組みをご確認いただけます。

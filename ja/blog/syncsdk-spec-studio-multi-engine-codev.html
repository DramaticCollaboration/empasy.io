5-Step Spec Studioと15種コーディング基盤切替：SyncSDKによる開発チーム協業（Co-Dev）設計

経営層・現場担当者のための3行要約
  • 従来の課題特定のAIコーディング製品1社へ固定すると価格改定や社内セキュリティ要件変化への対応が難しく、改修のたびに設計書とコードが乖離します。

  • 導入効果特定ベンダーに縛られず社内アーキテクチャ基準と最新設計ドキュメントの整合性を保てます。

開発組織がAIコーディング支援を本格導入すると、単一ベンダーへのロックインと、高速なコード変更による設計書・仕様書の陳腐化（ドキュメントドリフト）が大きな課題になります。

EmpasyはSyncSDKの15種マルチエンジン標準SPIとSyncVerseの5-Step Spec Studio・仕様逆同期（Living Spec）によってこれらを解決しています。

1. ICodingAgentClient SPI と15種エンジンの無停止ホットスワップ

sync-sdk-commonは15種のコーディング基盤をICodingAgentClientとCodingAgentTypeで4つの実行方式に統一しています。

  • SDK Native（1種）：ANTIGRAVITY
  • CLI Subprocess（11種）：CLAUDE_CODE、GITHUB_COPILOT、CODEX_CLI、GEMINI_CLI、CURSOR_CLI、CONTINUE、AIDER、GOOSE、MINI_SWE、CLINE、KIRO
  • Docker隔離実行（2種）：OPENHANDS、OPENSWE
  • REST API（1種）：EIGENT

CodingAgentRoutingProxyにより再起動なしで稼働エンジンを切り替えられ、エンジン別の既定モデルもSystemConfigHolder（sync.sdk.agent.default-model.<code_lower>）からDB動的に解決されます。

2. 5-Step Spec Studio と社内開発者 Co-Dev パイプライン

STEP 01
受入基準（AC）整理＆コードグラフ影響分析
業務要望を受入基準へ構造化し、4段階依存グラフで変更対象ファイルを特定
STEP 02
機能・画面仕様＆Decision Queue
詳細仕様・画面案を作成し、影響度別の未決事項キューで担当者が方針確定
STEP 03
技術仕様＆APIカバレッジゲート
DDL・REST API契約・対象focusFilesを実装前に検証し漏れを防止
STEP 04
SyncSDK実装＆4-Cycle品質検証
稼働エンジン（15種から選択）がfeat/* PRを作成しビルド・テストを自動検証
STEP 05
開発者Co-Dev・仕様逆同期＆SI納品物
ローカル検証・修正後にreverse-syncで仕様自動更新し4種納品ドキュメントを出力

3. Living Spec 逆同期とSI 4大納品ドキュメント自動生成

  • 仕様逆同期（LivingSpecReverseSyncService）：社内開発者がローカルIDEでエッジケースを補完・プッシュした際、実際のGit Diffから機能・API仕様を自動更新します。
  • SI 4大納品物一括出力（SpecDeliverableAndGovernanceSupport）：確定仕様からプログラム仕様書（HTML）・画面設計書（HTML）・テーブル定義書（CSV/XLSX）・単体テストシナリオ（CSV/XLSX）を一括生成できます。

4. ベンダー独立性とガバナンスの両立

差し替え可能なコーディング基盤、実装前の仕様ゲート、社内開発者によるレビュー、最新状態が保たれる納品物を一体運用することで、安心して開発生産性を高められます。

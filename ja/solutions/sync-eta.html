従来のスクリプト型QA

  • UIデザインやDOM構造変更時のセレクターエラーによるテスト停止
  • 単純なピクセル比較による誤検知(False Positive)の多発
  • リリースごとのテストスクリプト修正に膨大な工数を消費

SyncEta QAエージェント

  • Vision-LLMによる視覚的要素認識と実行時自己修復
  • ユーザーの実際の画面認知に基づく文脈的品質検証
  • エラー発生時の原因分析およびパッチスクリプトの自動生成
Technical Proof

Self-Healing コード自動修復の仕組み

ボタンクラス名が変更されても、Vision-LLMが文脈を分析してテストスクリプトをリアルタイムに自動補正します。

// Playwright Test Execution: tests/checkout.spec.ts
// [従来のコード: DOMクラス名変更により要素検索失敗] - await page.locator('button.btn-checkout-legacy').click(); // [SyncEta Self-Healing: Vision-LLMが決済ボタンを視覚認識し自動代替] + await page.locator('button:has-text("購入する"), #pay-submit').click();
[SyncEta Report] Selector healed automatically. Test run completed with 0 errors.

主要機能およびアーキテクチャ

01

Vision-LLM 自己修復 (Self-Healing)

単純なXPath/CSS依存から脱却し、画面内の位置関係とテキスト文脈を総合判断して壊れたセレクターを実行時にリアルタイム自己修復します。

02

Excelテストケースの直接自動実行

事前のレコーディングやコード記述なしで、QAチームが保有するExcelテスト仕様書をAIが直接解釈してPlaywright自動テストを実行します。

03

L1〜L5 階層別深層品質検証

L1(単純描画/クリック)からL3(動的変数キャプチャ)、L5(APIトランザクション整合性検証)まで多次元の品質を保証します。

04

年間LLMコスト最大99%削減 (TCO)

シナリオ生成時のみ1回LLMを呼び出し、反復回帰テストは録画されたエンジンレコードでゼロコスト実行して運用コストを削減します。

よくある質問 (FAQ)

SeleniumやPlaywrightと何が違いますか？
SyncEtaはVision-LLMを搭載し、UIやDOMが変更されても視覚的・文脈的に要素を再特定してテストスクリプトを自動修復します。
社内閉域網(オンプレミス)でも動作しますか？
はい、外部インターネット通信を行わないオンプレミスコンテナ環境やプライベートモデルとの連携に対応しています。
QAリソースの削減効果はどのくらいですか？
テストスクリプトのメンテナンスにかかる工数を80%以上削減できます。

Since SyncBoot is based on Spring Boot, you can apply the H2 Database settings just as you would in a typical Spring Boot application.
Below is how to configure H2 for **development/testing** purposes.

---

## 1. Add H2 Dependency to `pom.xml`

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

- Setting the scope to `runtime` means it will not be included during the build but will only be loaded at runtime.

---

## 2. `application.yml` (Memory Mode)

```yaml
spring:
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:mem:syncboot;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: update
    database-platform: org.hibernate.dialect.H2Dialect

# Enable H2 Console
spring.h2.console.enabled: true
spring.h2.console.path: /h2-console
```

- `jdbc:h2:mem:syncboot`: In-memory DB, data is lost upon server restart.
- `DB_CLOSE_DELAY=-1`: Keeps the session alive until the application shuts down.
- `/h2-console`: Allows DB access via a web browser.

---

## 3. (Optional) File Mode Usage

```yaml
spring:
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:file:./h2data/syncboot;AUTO_SERVER=TRUE
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: update
    database-platform: org.hibernate.dialect.H2Dialect

spring.h2.console.enabled: true
spring.h2.console.path: /h2-console
```

- In file mode, data is saved to a local file (`./h2data/syncboot.mv.db`).
- Adding `AUTO_SERVER=TRUE` allows access from multiple processes.

---

## 4. Applying H2 by Profile in SyncBoot

SyncBoot uses **environment-specific profiles** like `application-dev.yml`, so you can separate configurations to use H2 only in development mode and MySQL/Oracle in deployment mode.

Example:

```yaml
# application-dev.yml
spring:
  profiles: dev
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:mem:syncboot;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: update
    database-platform: org.hibernate.dialect.H2Dialect
spring.h2.console.enabled: true
spring.h2.console.path: /h2-console
```

In `application.yml`:

```yaml
spring:
  profiles:
    active: dev
```

## 5. How to Access

After starting the server, go to your browser:

```
http://localhost:8080/h2-console
```

- JDBC URL : `jdbc:h2:mem:syncboot`
- User Name : `sa`
- Password : (leave blank)

```sql
-- SyncBoot core table creation script for H2
-- Compatible with both memory mode and file mode

CREATE TABLE sys_user (
    id VARCHAR(36) PRIMARY KEY,
    username VARCHAR(100) NOT NULL,
    realname VARCHAR(100),
    password VARCHAR(100) NOT NULL,
    salt VARCHAR(50),
    avatar VARCHAR(255),
    birthday DATE,
    sex INT,
    email VARCHAR(100),
    phone VARCHAR(50),
    org_code VARCHAR(64),
    status INT,
    del_flag INT DEFAULT 0,
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by VARCHAR(50),
    update_time TIMESTAMP
);

CREATE TABLE sys_role (
    id VARCHAR(36) PRIMARY KEY,
    role_name VARCHAR(100) NOT NULL,
    role_code VARCHAR(100) NOT NULL,
    description VARCHAR(255),
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by VARCHAR(50),
    update_time TIMESTAMP
);

CREATE TABLE sys_user_role (
    id VARCHAR(36) PRIMARY KEY,
    user_id VARCHAR(36) NOT NULL,
    role_id VARCHAR(36) NOT NULL,
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE sys_permission (
    id VARCHAR(36) PRIMARY KEY,
    parent_id VARCHAR(36),
    name VARCHAR(100),
    url VARCHAR(255),
    component VARCHAR(255),
    perms VARCHAR(255),
    perms_type VARCHAR(2),
    sort_no INT,
    menu_type INT,
    status INT,
    icon VARCHAR(100),
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,

CREATE TABLE sys_role_permission (
    id VARCHAR(36) PRIMARY KEY,
    role_id VARCHAR(36) NOT NULL,

    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP

-- Add indexes
CREATE INDEX idx_sys_user_username ON sys_user(username);
CREATE INDEX idx_sys_user_role_uid ON sys_user_role(user_id);

CREATE INDEX idx_sys_permission_pid ON sys_permission(parent_id);
CREATE INDEX idx_sys_role_permission_rid ON sys_role_permission(role_id);
CREATE INDEX idx_sys_role_permission_pid ON sys_role_permission(permission_id);
```

## 7. Precautions when converting MySQL → H2

| MySQL                                                   | H2 Conversion Rule                                       |
| ------------------------------------------------------- | -------------------------------------------------------- |
| `AUTO_INCREMENT`                                        | Use `IDENTITY`                                           |
| `DATETIME` / `TIMESTAMP`                                | `TIMESTAMP` (H2 default)                                 |
| `ENGINE=InnoDB`                                         | Remove                                                   |
| `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | `DEFAULT CURRENT_TIMESTAMP` (H2 does not have `ON UPDATE`) |
| `TINYINT(1)`                                            | `BOOLEAN` or `INT`                                       |

---

## 8. How to automatically convert the entire SyncBoot schema to H2

1. Extract schema from current MySQL using `mysqldump`

   ```bash
   mysqldump -u root -p --no-data syncboot > schema.sql
   ```

2. Remove MySQL-specific syntax that cannot be executed in the H2 Database web console or CLI (`ENGINE=`, `CHARSET=`, `ON UPDATE CURRENT_TIMESTAMP`, etc.)
3. Type conversion

- `bigint(20)` → `BIGINT`
- `varchar(255)` → Can be used as is
- `int(11)` → `INT`

4. Date fields: `datetime` → `timestamp`

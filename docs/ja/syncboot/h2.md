SyncBootはSpring Bootベースであるため、H2 Databaseの設定も一般的なSpring Bootの方式をそのまま適用すればよいです。
以下は**開発/テスト用**にH2を使用するように設定する方法です。

---

## 1. `pom.xml`にH2の依存関係を追加

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

- scopeを`runtime`にすると、ビルド時には含まれず、実行時にのみロードされます。

---

## 2. `application.yml` (メモリモード)

```yaml
spring:
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:mem:syncboot;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: update
    database-platform: org.hibernate.dialect.H2Dialect

# H2コンソールの有効化
spring.h2.console.enabled: true
spring.h2.console.path: /h2-console
```

- `jdbc:h2:mem:syncboot`: インメモリDB、サーバー再起動時にデータが消去されます。
- `DB_CLOSE_DELAY=-1`: アプリケーション終了前までセッションを維持します。
- `/h2-console`: ウェブブラウザでDBへのアクセスが可能です。

---

## 3. (オプション) ファイルモードでの使用

```yaml
spring:
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:file:./h2data/syncboot;AUTO_SERVER=TRUE
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: update
    database-platform: org.hibernate.dialect.H2Dialect

spring.h2.console.enabled: true
spring.h2.console.path: /h2-console
```

- ファイルモードでは、データがローカルファイル(`./h2data/syncboot.mv.db`)に保存されます。
- `AUTO_SERVER=TRUE`を付けると、複数のプロセスからアクセス可能です。

---

## 4. SyncBootでプロファイルごとにH2を適用する

SyncBootは`application-dev.yml`のような**環境別プロファイル**を使用するため、開発モードでのみH2を使用し、デプロイモードではMySQL/Oracleなどを使用するように分けることができます。

例：

```yaml
# application-dev.yml
spring:
  profiles: dev
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:mem:syncboot;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: update
    database-platform: org.hibernate.dialect.H2Dialect
spring.h2.console.enabled: true
spring.h2.console.path: /h2-console
```

`application.yml`では：

```yaml
spring:
  profiles:
    active: dev
```

---

## 5. アクセス方法

サーバー実行後、ブラウザで：

```
http://localhost:8080/h2-console
```

- JDBC URL : `jdbc:h2:mem:syncboot`
- User Name : `sa`
- Password : (空欄)

## 6. H2 DDLの例

```sql
-- H2用のSyncBootコアテーブル作成スクリプト
-- メモリモードまたはファイルモードの両方で互換可能

CREATE TABLE sys_user (
    id VARCHAR(36) PRIMARY KEY,
    username VARCHAR(100) NOT NULL,
    realname VARCHAR(100),
    password VARCHAR(100) NOT NULL,
    salt VARCHAR(50),
    avatar VARCHAR(255),
    birthday DATE,
    sex INT,
    email VARCHAR(100),
    phone VARCHAR(50),
    org_code VARCHAR(64),
    status INT,
    del_flag INT DEFAULT 0,
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by VARCHAR(50),
    update_time TIMESTAMP
);

CREATE TABLE sys_role (
    id VARCHAR(36) PRIMARY KEY,
    role_name VARCHAR(100) NOT NULL,
    role_code VARCHAR(100) NOT NULL,
    description VARCHAR(255),
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by VARCHAR(50),
    update_time TIMESTAMP
);

CREATE TABLE sys_user_role (
    id VARCHAR(36) PRIMARY KEY,
    user_id VARCHAR(36) NOT NULL,
    role_id VARCHAR(36) NOT NULL,
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE sys_permission (
    id VARCHAR(36) PRIMARY KEY,
    parent_id VARCHAR(36),
    name VARCHAR(100),
    url VARCHAR(255),
    component VARCHAR(255),
    perms VARCHAR(255),
    perms_type VARCHAR(2),
    sort_no INT,
    menu_type INT,
    status INT,
    icon VARCHAR(100),
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    update_by VARCHAR(50),
    update_time TIMESTAMP
);

CREATE TABLE sys_role_permission (
    id VARCHAR(36) PRIMARY KEY,
    role_id VARCHAR(36) NOT NULL,
    permission_id VARCHAR(36) NOT NULL,
    create_by VARCHAR(50),
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- インデックスの追加
CREATE INDEX idx_sys_user_username ON sys_user(username);
CREATE INDEX idx_sys_user_role_uid ON sys_user_role(user_id);
CREATE INDEX idx_sys_user_role_rid ON sys_user_role(role_id);
CREATE INDEX idx_sys_permission_pid ON sys_permission(parent_id);
CREATE INDEX idx_sys_role_permission_rid ON sys_role_permission(role_id);
CREATE INDEX idx_sys_role_permission_pid ON sys_role_permission(permission_id);
```

## 7. MySQL → H2 変換時の注意事項

| MySQL                                                   | H2 変換ルール                                        |
| ------------------------------------------------------- | ---------------------------------------------------- |
| `AUTO_INCREMENT`                                        | `IDENTITY`を使用                                     |
| `DATETIME` / `TIMESTAMP`                                | `TIMESTAMP` (H2のデフォルト値)                       |
| `ENGINE=InnoDB`                                         | 削除                                                 |
| `DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | `DEFAULT CURRENT_TIMESTAMP` (H2には`ON UPDATE`がない) |
| `TINYINT(1)`                                            | `BOOLEAN` または `INT`                               |

## 8. SyncBootの全体スキーマをH2に自動変換する方法

1. 現在のMySQLから`mysqldump`でスキーマを抽出

   ```bash
   mysqldump -u root -p --no-data syncboot > schema.sql
   ```

2. H2 DatabaseのWebコンソールまたはCLIで実行不可能なMySQL専用の構文を削除 (`ENGINE=`, `CHARSET=`, `ON UPDATE CURRENT_TIMESTAMP` など)
3. 型変換

- `bigint(20)` → `BIGINT`
- `varchar(255)` → そのまま使用可能
- `int(11)` → `INT`

4. 日付フィールド: `datetime` → `timestamp`

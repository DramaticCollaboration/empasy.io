ストーリーポイントガイド：アジャイルチームのための作業見積もり方法 ​

ストーリーポイントとは？ ​

ストーリーポイントは、作業の 規模、複雑さ、不確実性 を相対的に見積もる単位です。絶対的な時間と直接マッピングするものではなく、スプリント単位での合理的な作業量の把握とチームのスケジュール見積もりを目的とします。

❌ 「5ポイント = 1ポイントの5倍の時間」というアプローチは間違っています

フィボナッチ数列を使用する理由 ​

ストーリーポイントの見積もりには、一般的に 1, 2, 3, 5, 8, 13, 21... のようなフィボナッチ数列を使用します。このように連続した数字ではない数列を使用する理由は以下の通りです。

  • 差が次第に大きくなり、不確実性を反映します
  • 5と6の差よりも、5と8の差の方がより明確です
  • 大きな作業になるほど、複雑さとリスクが指数関数的に増加することを反映します
  • 結果として、チームの合意形成が容易になり、過大/過小見積もりを減らすことができます

ストーリーポイントの活用例 ​

作業項目ポイント説明
ユーザー調査3ポイント比較的軽い労力が必要な作業
ワイヤーフレーム5ポイントユーザー調査後に進める簡単な作業
UIデザイン8ポイントチーム内での調整が必要な作業
開発作業13ポイント多くの要素が関与し、複雑な作業
QAテスト8ポイント複雑だが管理可能なレベルの作業

基準となる課題の例 ​

ストーリーポイント 5：ユーザーパスワードリセット機能 ​

Doneの定義

  • パスワード変更機能の実装
  • メール認証機能の実装
  • パスワードルールの遵守 (英数字混合など)

補足の考慮事項

  • DBテーブルの設計
  • メールの送受信環境
  • 例外事項は考慮しなくてもよい

ストーリーポイント 13：クレジットカード決済機能 ​

Doneの定義

  • 商品決済機能の実装
  • マイページで購買履歴の照会が可能
  • 管理者も確認可能

補足の考慮事項

  • カード登録機能は既に存在している
  • DB設計が必要
  • エラーパターンは考慮しなくてもよい

注意事項：間違った使い方 ​

時間をそのまま代入する方式は避けるべきです

  • ❌ 「4時間の業務 = 1ポイント」 → 既存のやり方と変わらない
  • ❌ 「5ポイント = 1ポイントの5倍の時間」

正しい意味：1ポイントよりも5倍複雑だという意味です。このような間違ったアプローチはストーリーポイントの本質を崩します。

リファクタリングと品質の考慮事項 ​

すべてのストーリーには、以下の2つの要素が必ず含まれていなければなりません。

  1. 正しく動作する機能
  2. 適切に動作する品質

1つ目の要素だけを満たし、2つ目の要素を無視すると、ストーリーポイントは不完全です。リファクタリング作業も、品質向上（技術的負債の解消）の観点からポイントを付与することができます。

注意：ストーリーポイントは、個人の成果比較用には絶対に使用しないでください。これは純粋にチーム単位のツールです。

核心のまとめ ​

  • ストーリーポイントは 相対的な見積もり単位 です
  • 時間換算ではなく、作業の 複雑さ/不確実性の比較 が目的です
  • フィボナッチ数列を使用し、大きな作業ほどリスクが大きくなるという点を反映します
  • チームの合意基準(3, 5, 8, 13など)を決めておき、新しい作業と比較して決定します
  • 間違った時間対応の方式は避け、品質基準を必ず反映させます

ストーリーポイント会議の進行ガイド ​

会議アジェンダ ​

オープニング (5分) ​

  • 会議の目的説明：今回のスプリントの作業難易度/複雑さを相対的に見積もる
  • 絶対的な時間単位ではなく、相対的な規模の比較を通じて合意することの強調

基本概念のリマインド (10分) ​

  • ストーリーポイントの定義：作業の規模、複雑さ、不確実性を表す単位
  • 時間と1:1でマッピングしない (❌ 「5ポイント = 1ポイントの5倍の時間」)
  • フィボナッチ数列を使用する理由の説明 (1, 2, 3, 5, 8, 13, 21...)

基準事例の共有 (10分) ​

  • ストーリーポイントの例の共有 (ユーザー調査 → 3、ワイヤーフレーム → 5 など)
  • 具体的な基準課題の検討 (5ポイント：パスワードリセット、13ポイント：クレジットカード決済)

間違った使い方の注意 (5分) ​

  • 時間をそのまま代入しないことを強調
  • 「5ポイント = 1ポイントの5倍の時間」 ❌
  • 正しい解釈：「1ポイントよりも5倍複雑だ」

リファクタリングおよび品質の考慮 (10分) ​

  • すべてのストーリーには [1] 正しく動作 + [2] 適切に動作(品質) を含める必要がある
  • リファクタリング/技術的負債の改善も状況に応じてポイント策定が必要
  • 個人の成果比較用ではないことを再強調

実際の作業の見積もり (30〜40分) ​

  • バックログアイテムを1つずつ確認
  • 基準事例と比較して議論
  • チーム合意 → フィボナッチ数の中から1つを決定 (例：3, 5, 8, 13)
  • 問題や意見の対立がある場合は妥協点を見つける

まとめ (5分) ​

  • 会議で決めたストーリーポイントの結果の整理
  • 次のスプリント計画時に反映する予定であることを知らせる
  • 「ストーリーポイントは、チームのスケジュールを素早く簡単に見積もるためのツール」であることを再強調

ストーリーポイントはチームの生産性とスケジュール管理に有用なツールですが、正しく理解して使用した時にその真の価値を発揮します。

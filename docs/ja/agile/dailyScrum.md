# ✅ デイリースクラムの進行方法

1. **時間と場所の固定**

- 毎日同じ時間 (例：午前9時)
- 同じ場所 (会議室 または オンラインビデオ会議)

2. **参加者**

- 開発チーム全員 (開発者、QAなど)
- スクラムマスター (進行補助)、POはオブザーバーとして参加可能

3. **進行方式**

- 時間は **15分以内**
- チームメンバーが **順番に共有**
- **3つの質問**に合わせて簡潔に話す

  1. 昨日何をしましたか？
  2. 今日は何をする予定ですか？
  3. 進行を妨げる障害物はありますか？

4. **重要な原則**

- 詳細な技術的説明 ❌ → 「共有」中心
- 障害物はスクラム終了後に別途議論
- 報告ではなく **チームの同期が目的**

# 🎤 デイリースクラム 実際の進行例スクリプト

## 基本情報

- **時間**: 毎朝10:00 (15分以内)
- **参加者**: 開発チーム全体、スクラムマスター、必要に応じてプロダクトオーナー(PO)
- **形式**: 立ったまま進行 (リモート時はビデオ会議)

---

## 1. 開始の挨拶および会議の目的の確認 (2分)

**スクラムマスター**:

> 「おはようございます。デイリースクラムを始めます。今日も各自、昨日やったこと、今日やること、そして障害要素があれば共有をお願いします。」

---

## 2. チームメンバー別の進捗状況の共有 (10分)

### 開発のキムさん

> 「昨日はユーザーログインAPIの開発を完了しました。今日はユーザープロフィール照会機能を実装する予定です。現在、特に障害要素はありません。」

### デザインのイさん

> 「昨日は決済ページのUIデザインを完了し、開発チームに引き渡しました。今日は管理者ページのデザインを開始する予定です。ただ、開発パートとの協議が必要な部分があるので、午後に短くミーティングをお願いできますか？」

**スクラムマスター**:

> 「はい、会議後に関連チームメンバーとスケジュールを調整します。」

### バックエンドのパクさん

> 「昨日はDB最適化作業を行い、今日はパフォーマンステストを行う予定です。ただ、テストサーバーのCPU使用率が高いので、モニタリングが必要だと思います。」

**スクラムマスター**:

> 「障害要素として記録しておき、会議後にインフラチームと協議してみます。」

### QAのチョンさん

> 「昨日はログイン機能のテストを完了し、今日は新たに追加された決済機能のテストを開始する予定です。テストシナリオの中で開発チームの確認が必要な部分がいくつかあります。」

**スクラムマスター**:

> 「会議後にすぐに関連開発者とお繋ぎします。」

---

## 3. 障害要素の要約および対応計画の策定 (2分)

**スクラムマスター**:

> 「これまでに共有された障害要素をまとめると：
>
> 1. デザインと開発の協議ミーティングが必要
> 2. テストサーバーのCPU使用率の問題
> 3. QAテストシナリオの確認が必要
>
> この3つの項目について、私が各担当者と調整します。」

---

## 4. 会議の終了 (1分)

**スクラムマスター**:

> 「皆さん、今日のやるべきことが明確になり、障害要素も把握できました。会議はここで終了し、必要な方は別途議論を続けてください。皆さん、今日も頑張りましょう！」

---

## 💡 デイリースクラムの効果的な運用ヒント

- **時間厳守**: 15分のルールを守るため、立ったままでの会議を推奨
- **問題解決会議の禁止**: 深い議論は別途時間を確保して進行
- **全チームメンバーの参加**: 満遍なく発言できるように雰囲気作り
- **視覚的な補助ツールの活用**: カンバンボード、タスク管理ツールなどを併用
- **障害要素への集中**: 問題解決のためのアクションプランを必ず策定

---

## 📝 記録の例

| 担当者 | 昨日やったこと | 今日やること | 障害要素 |
| ------ | -------------- | ------------ | -------- |
| 開発キム | ログインAPI開発完了 | プロフィール照会機能実装 | なし |
| デザインイ | 決済ページUI完了 | 管理者ページデザイン開始 | 開発チームと協議が必要 |
| バックエンドパク | DB最適化作業 | パフォーマンステスト進行 | テストサーバーCPU使用率問題 |
| QAチョン | ログイン機能テスト完了 | 決済機能テスト開始 | テストシナリオの確認が必要 |

# ✅ デイリースクラム進行用チェックリスト

## 📌 進行者(スクラムマスター)チェックリスト

- [ ] 毎日同じ時間/場所(あるいはオンライン)で開始したか？
- [ ] 15分以内で終わらせる準備ができているか？
- [ ] 各チームメンバーが **昨日/今日/障害物** の3項目だけを共有するように誘導したか？
- [ ] 共有された **障害物(Blocking Issue)** は別途Follow-upとして記録したか？
- [ ] スクラム終了後、課題解決のための追加ミーティングが必要な人だけを招集したか？

---

## 📌 チームメンバー個別の共有チェックリスト

- [ ] 昨日私が完了したことは？
- [ ] 今日私がやるべきことは？
- [ ] 進行を妨げる障害物はあるか？

👉 共有は **短く明確に (1〜2文)**
👉 問題解決の議論は ❌ (スクラムの後に別途)

---

## 📝 チームメンバー共有例のテンプレート

```
[名前]
- 昨日:
- 今日:
- 障害物:
```

---

## 📊 チーム全体のスクラムボード例 (ホワイトボード / オンラインコラボレーションツール)

| 名前 | 昨日やったこと | 今日やること | 障害物 (Blocking Issue) |
| ---- | -------------- | ------------ | ----------------------- |
| チョルス | ログインAPIリファクタリング完了 | Googleソーシャルログイン連携開始 | Google OAuthドキュメントにアクセス不可 |
| ヨンヒ | 会員登録機能のテストケース作成と一部実行 | 会員登録機能全体のテストとバグレポート | テストサーバーが頻繁に切断される |
| ミンス | ダッシュボードUI作業 | チャートライブラリの適用とAPI連携 | 最新API仕様書が共有されていない |

---

👉 このようにすれば、チームメンバーは毎日 **チェックリストに基づいて話すだけでよく**、スクラムマスターは **テーブルを更新するだけ** で記録と共有が同時に解決します。

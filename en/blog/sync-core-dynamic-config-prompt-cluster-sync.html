Updating AI Prompts & Policies Without Restarts: sys_config & sys_prompt_template Cluster Sync

3-Line Executive & Business Summary
  • ChallengeHardcoding timeouts, default AI models, and agent prompts in code or static YAML forces full rebuilds and restarts for minor operational tweaks.
  • Approachsync-core stores sys_config and versioned sys_prompt_template entries in PostgreSQL and broadcasts hot cache updates across all JVM nodes via ClusterEventBroadcaster.
  • ImpactOperators tune policies safely without downtime, roll back prompt versions in one click, and protect secrets with AES-256 encryption and UI masking.

In production AI systems, operational parameters change far more frequently than application code—LLM timeouts, default models, margin thresholds, integration endpoints, and agent system prompts. Keeping them hardcoded in Java constants or static YAML triggers unnecessary rebuilds and risks configuration drift across scaled-out nodes.

Empasy solves this across every SyncSeries module through sync-core: database-backed runtime config (sys_config), versioned AI prompts (sys_prompt_template & sys_prompt_history), and ClusterEventBroadcaster.

1. Zero-Restart Cluster Sync Pipeline

STEP 01
Admin Edit & Check
Updates config or prompt in Admin UI with optional socket check
→
STEP 02
Persist & Encrypt
Commits to PostgreSQL with AES-256 secret encryption & history
→
STEP 03
Broadcast Event
ClusterEventBroadcaster publishes via Redis Pub/Sub or shared mem
→
STEP 04
Hot Cache Reload
SystemConfigHolder & SystemPromptHolder refresh on every node

2. Dynamic Configuration (sys_config) & Secret Protection

  • In-Memory Fast Path (SystemConfigHolder): Business services read typed policies directly from memory without repetitive DB round trips.
  • AES-256 Encryption & Masking (AesEncryptUtil): Entries marked is_secret=true store encrypted ciphertext in PostgreSQL and display masked previews in admin views.

3. Versioned AI Prompts (sys_prompt_template) & One-Click Rollback

  • Structured Prompt Governance: Tracks app_code, prompt_code, system_prompt, user_prompt_template, variables_schema, model_override, and temperature centrally.
  • Instant Version Recovery (sys_prompt_history): Every edit records an immutable version snapshot and change_reason, allowing one-click rollback if output quality regresses.

4. ClusterEventBroadcaster: Redis Pub/Sub With Shared-Memory Fallback

ClusterEventBroadcaster propagates CONFIG_REFRESH, PROMPT_REFRESH, POLICY_CACHE_SYNC, and WEBSOCKET_BROADCAST events over channel syncseries:cluster:events:

  • Self-Echo Suppression: Each ClusterEventMessage tags its originInstanceId so the publisher skips redundant self-processing.
  • Dual Backing Stores: Uses RedisClusterStateBackingStore in multi-node clusters and falls back cleanly to SharedMemoryClusterStateBackingStore on single-host setups, complemented by DistributedLockExecutor for concurrency safety.

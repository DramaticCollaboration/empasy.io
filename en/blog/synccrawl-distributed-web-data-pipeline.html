The accuracy of any corporate RAG search system depends directly on the cleanliness and freshness of its source data. Beyond internal policies, teams increasingly need public regulations, industry standards, pricing benchmarks, and technical documentation refreshed on schedule.

Storing raw web pages injects menus, banners, and scripts that confuse retrieval, while layout changes routinely break fixed scraping rules. Empasy's SyncCrawl organizes web-to-RAG collection into a resilient 4-stage pipeline.

2. Hybrid Static & Playwright Browser Collection

  • Autonomous Strategy Profiling: Inspects initial responses so static pages use fast HTTP fetchers and only JavaScript-rendered SPAs allocate Playwright browser workers.
  • Self-Healing Selectors (healed_selector): When a target site updates CSS classes or DOM nesting, SyncCrawl re-evaluates live DOM context to recover extraction selectors without interrupting scheduled batches.
  • Compliance & Politeness Controls: Verifies robots.txt rules automatically and enforces per-domain concurrency caps and request delays.

3. Content Extraction, PII Masking & Diff Tracking

  • Structure-Preserving Markdown: Strips navigation chrome and scripts while retaining heading hierarchy, lists, and tables for accurate retrieval.
  • Pre-Storage PII Redaction: Masks phone numbers, emails, and other accidental personal identifiers before storing documents.
  • Hash-Based Change Diffs (crawl_change_diff): Skips re-embedding unchanged pages to save compute and generates concise change summaries when updates occur.

4. Feeding Internal Knowledge Search (SyncInsight)

Cleaned documents are chunked with controlled overlap and indexed into PostgreSQL 18.6 pgvector and BM25 alongside source URLs and timestamps, enabling cited answers across SyncInsight.

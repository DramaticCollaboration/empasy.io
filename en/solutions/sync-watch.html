What is Empasy SyncWatch?

How It Works

1

Global Threat Feed Ingestion & CWE/MITRE Normalization

Collects external threat feeds (`watch_feed_source`) and security audit reports, normalizing them into a unified CWE, MITRE ATT&CK, and SBOM ecosystem ledger (`watch_security_advisory`).

2

Dual Rule Compilation & Self-Sandbox Verification

Simultaneously compiles code audit rules and runtime virtual patch rules, testing each against attack (Positive) and benign (Negative) sample payloads to guarantee zero false positives.

3

Real-Time Broadcast to SyncVerse & SyncAPIM with Feedback Telemetry

Broadcasts verified security packs enterprise-wide and tracks repository audit findings and gateway block counts in the central dispatch ledger (`watch_dispatch_history`).

Frequently Asked Questions (FAQ)

How fast are defense rules deployed when a new CVE vulnerability is disclosed?
As soon as a new advisory is collected from NVD, CISA KEV, OSV.dev, GHSA, or KISA, SyncWatch normalizes the CVE, runs sandbox verification, and broadcasts both the SyncVerse code audit pack and SyncAPIM runtime virtual patch pack within minutes.
How does SyncWatch prevent auto-compiled rules from blocking legitimate traffic (False Positives)?
SyncWatch never broadcasts unverified rules. Every compiled rule must pass an isolated sandbox test demonstrating 100% True Positive detection on exploit samples and 0% False Positive hits on normal production payloads.
Can we upload internal penetration test reports or custom security advisories?
Yes. In addition to automated global threat channels, security engineers can upload internal audit documents or custom advisories, which SyncWatch normalizes into CWE/MITRE entries and compiles into dual enforcement rules.

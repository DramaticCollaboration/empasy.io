2026-11-23 • 읽는 시간 약 6분 • 공통 코어 · 동적 설정 · 클러스터 동기화

운영 재시작 없이 AI 프롬프트와 정책을 바꾸는 법: sys_config · sys_prompt_template 클러스터 동기화

경영진 · 현업 담당자를 위한 3줄 요약
  • 기존 문제타임아웃·임계치·기본 AI 모델명·에이전트 시스템 프롬프트를 소스코드나 정적 YAML에 하드코딩하면 작은 정책 수정에도 빌드와 서버 재기동이 필요합니다.
  • 해결 방식sync-core는 sys_config와 sys_prompt_template(이력 롤백 포함)을 PostgreSQL에서 중앙 관리하고, 변경 즉시 ClusterEventBroadcaster로 전 JVM 인스턴스 캐시를 무중단 갱신합니다.
  • 기대 효과운영 중단 없이 정책·프롬프트를 안전하게 실험하고 문제 시 이전 버전으로 원클릭 롤백하며, 민감 키는 AES-256 암호화와 화면 마스킹으로 보호합니다.

  2. 2. 동적 환경설정(sys_config)과 시크릿 보호 설계
  3. 3. 동적 AI 프롬프트(sys_prompt_template)와 원클릭 버전 롤백

AI 에이전트와 기업 업무 시스템을 실제 운영하다 보면 코드 로직보다 훨씬 자주 바뀌는 값이 있습니다. LLM 타임아웃, 기본 추론 모델명, 마진 보호 하한선, 외부 API 엔드포인트, 그리고 에이전트 판정용 시스템 프롬프트입니다. 이 값들이 Java 상수나 정적 application.yml에 박혀 있으면 사소한 문구 보정 하나에도 Git 커밋 -> CI 빌드 -> 컨테이너 재배포가 뒤따르고, 멀티 인스턴스 환경에서는 노드 간 설정 불일치까지 발생합니다.

엠파시는 전 제품군이 공유하는 플랫폼 코어(sync-core)에 DB 기반 동적 환경설정(sys_config), 버전 관리형 동적 프롬프트(sys_prompt_template / sys_prompt_history), 그리고 멀티 인스턴스 무중단 브로드캐스터(ClusterEventBroadcaster)를 내장해 이 문제를 해결했습니다.

1. 무중단 설정 · 프롬프트 클러스터 동기화 파이프라인

관리자가 Admin UI(/system/config 또는 /system/prompt)에서 값을 저장하면 다음 4단계가 밀리초 단위로 실행됩니다.

STEP 01
Admin UI 수정 · 진단
설정·프롬프트 편집 및 원격 소켓 연결 사전 진단(필요 시)
→
STEP 02
DB 영속화 · 암호화
PostgreSQL 저장, 민감 키 AES-256 암호화 및 버전 이력 적재
→
STEP 03
클러스터 이벤트 전파
ClusterEventBroadcaster가 Redis Pub/Sub / 공유메모리 발행
→
STEP 04
전 노드 캐시 갱신
각 인스턴스의 SystemConfigHolder · SystemPromptHolder 즉시 리로드

2. 동적 환경설정(sys_config)과 시크릿 보호 설계

sys_config 테이블은 config_category(LLM_API, STORAGE, SECURITY, SYSTEM_OPS, AGENT_POLICY, JIRA 등), config_key, config_value, default_value, value_type, is_secret, is_dynamic 컬럼으로 정책을 구조화합니다.

  • 인메모리 즉시 조회(SystemConfigHolder): 서비스 코드는 매번 DB를 조회하지 않고 SystemConfigHolder.getValue(key, defaultVal)로 인메모리 캐시에서 즉시 값을 읽습니다.
  • AES-256 양방향 암호화 및 화면 마스킹(AesEncryptUtil): is_secret=true 항목(API Key, Token, DB 비밀번호)은 DB에 암호문으로 저장되고, 관리자 조회 응답에서는 sk-ant-*** 형태로 마스킹해 평문 노출을 방지합니다.

3. 동적 AI 프롬프트(sys_prompt_template)와 원클릭 버전 롤백

에이전트의 시스템 프롬프트, 라우팅 프롬프트, NL2SQL 생성 프롬프트, 보안 룰 컴파일 프롬프트는 소스코드가 아닌 sys_prompt_template 테이블에서 app_code, prompt_code, system_prompt, user_prompt_template, variables_schema, model_override, temperature 단위로 관리합니다.

  • 변경 이력 자동 스냅샷(sys_prompt_history): 프롬프트를 수정할 때마다 변경 사유(change_reason)와 증가된 version 번호로 이전 전문이 자동 보관됩니다.
  • 원클릭 롤백: 새 프롬프트 적용 후 응답 품질이나 형식이 기대와 다르면 코드 롤백 없이 관리자 화면에서 직전 버전으로 즉시 되돌릴 수 있습니다.

4. ClusterEventBroadcaster: Redis Pub/Sub 및 공유 메모리 자동 폴백

스케일아웃된 다중 JVM 인스턴스 중 한 노드에서만 설정이 바뀌면 나머지 노드는 옛 캐시를 계속 참조하는 문제가 생깁니다. ClusterEventBroadcaster는 단일 채널(syncseries:cluster:events)을 통해 CONFIG_REFRESH, PROMPT_REFRESH, POLICY_CACHE_SYNC, WEBSOCKET_BROADCAST 이벤트를 클러스터 전역으로 전파합니다.

  • 자기 에코 자동 무시: 모든 메시지(ClusterEventMessage)에 고유 originInstanceId를 담아 발행 노드가 스스로의 이벤트를 중복 처리하지 않도록 방지합니다.
  • 환경별 BackingStore 자동 선택: 운영·통합 클러스터에서는 RedisClusterStateBackingStore(Redis Pub/Sub)로 멀티 호스트를 동기화하고, 로컬 개발이나 단일 호스트 환경에서는 SharedMemoryClusterStateBackingStore로 자동 폴백해 인프라 의존성 없이 동일하게 동작합니다.
  • 분산 락(DistributedLockExecutor): 동시 수정이나 스케줄러 중복 실행이 필요한 구간에서는 분산 락으로 경합을 안전하게 제어합니다.

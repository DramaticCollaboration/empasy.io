5-Step Spec Studio와 15대 코딩 엔진 핫스왑: SyncSDK 기반 개발팀 협업(Co-Dev) 아키텍처

경영진 · 현업 담당자를 위한 3줄 요약
  • 기존 문제특정 AI 코딩 도구 하나에만 의존하면 요금 정책 변경·모델 성능 변화·사내 보안 기준에 유연하게 대응하기 어렵고, 코드 수정 후 설계 문서가 즉시 낡아버립니다.
  • 해결 방식SyncSDK(ICodingAgentClient)로 15대 코딩 엔진을 런타임 핫스왑하고, SyncVerse 5-Step Spec Studio에서 스펙 확정 -> PR 생성 -> 개발자 검증 -> Living Spec 역동기화 및 SI 4대 산출물까지 일관 관리합니다.
  • 기대 효과벤더 종속 없이 사내 개발팀의 코드 품질 기준과 SI 납품 문서 정합성을 함께 유지할 수 있습니다.

기업 개발 조직이 AI 코딩 에이전트를 실무에 도입할 때 가장 먼저 부딪히는 현실적인 문제는 두 가지입니다. 첫째, 특정 벤더의 CLI나 IDE 도구 하나에 파이프라인을 고정하면 모델 단가·성능·보안 요구사항이 바뀔 때마다 전체 워크플로우를 다시 뜯어고쳐야 합니다. 둘째, AI가 빠르게 코드를 작성하더라도 요구사항 명세, API 계약, 테이블 정의서, 테스트 시나리오가 코드와 어긋나는 문서 드리프트가 누적됩니다.

엠파시는 이 두 문제를 구조적으로 풀기 위해 SyncSDK 다중 엔진 표준 SPI(15대 코딩 엔진 핫스왑)와 SyncVerse 5-Step Spec Studio + 개발자 Co-Dev 역동기화 체계를 설계했습니다.

1. ICodingAgentClient SPI와 15대 코딩 엔진 런타임 핫스왑

sync-sdk-common은 개별 코딩 도구의 실행 방식을 ICodingAgentClient 인터페이스 하나로 추상화하고, CodingAgentType 레지스트리를 통해 15대 엔터프라이즈·오픈소스 코딩 엔진을 4가지 실행 유형으로 통합 지원합니다.

  • SDK Native (1종): ANTIGRAVITY (Google Antigravity SDK v2.0 멀티 에이전트 하네스)
  • CLI Subprocess (11종): CLAUDE_CODE, GITHUB_COPILOT, CODEX_CLI, GEMINI_CLI, CURSOR_CLI, CONTINUE, AIDER, GOOSE, MINI_SWE, CLINE, KIRO
  • Docker Container 격리 실행 (2종): OPENHANDS, OPENSWE
  • REST API 연동 (1종): EIGENT

CodingAgentRoutingProxy는 관리자 화면에서 활성 엔진, CLI 경로, 엔드포인트, 타임아웃을 바꾸는 즉시 서비스 재시작 없이 다음 작업부터 새 엔진으로 라우팅합니다. 각 엔진의 기본 추론 모델 또한 SystemConfigHolder(sync.sdk.agent.default-model.<code_lower>)를 통해 DB에서 동적으로 조회합니다.

2. 5-Step Spec Studio와 사내 개발자 Co-Dev 파이프라인

단순 프롬프트 한 줄로 곧장 프로덕션 소스를 수정하는 대신, SpecStudioController는 요구사항 정제부터 사내 개발자 로컬 검증·승인까지 5단계 게이트를 순서대로 밟습니다.

STEP 01
요구사항 AC 정제 & 코드 그래프 영향도 분석
자연어 요구를 수용 기준(AC-01~)으로 구조화하고 4단계 코드 그래프로 변경 대상 파일 범위 식별
STEP 02
상세 기능 · 화면 명세 & Decision Queue
기능·와이어프레임 명세 도출, L1/L2/L3 영향도별 미결사항 결정 대기열에서 담당자 의사결정 확정
STEP 03
기술 스펙 & API 커버리지 게이트
DDL 스키마, REST API 계약, 집중 수정 파일(focusFiles) 바인딩 및 누락 API 사전 보완
STEP 04
SyncSDK 슬라이스 코딩 & 4-Cycle 검증
활성 코딩 엔진(15종 중 선택)이 feat/* 브랜치 생성, 빌드·테스트 자가 점검 후 PR 상신
STEP 05
개발자 Co-Dev · Living Spec 역동기화 & SI 산출물
사내 개발자 로컬 검증·보완 후 reverse-sync로 명세 자동 갱신 및 SI 4대 납품 산출물 원클릭 출력

3. Living Spec 역동기화와 SI 4대 납품 산출물 자동 생성

실제 엔터프라이즈·SI 프로젝트에서는 AI가 PR을 올린 뒤 사내 개발자가 엣지 케이스나 도메인 예외 로직을 로컬 IDE에서 직접 보완하는 경우가 많습니다. 이때 설계 문서를 수동으로 고치지 않으면 문서와 코드가 다시 분리됩니다.

  • Living Spec 역동기화(LivingSpecReverseSyncService): 사내 개발자가 작업 브랜치에 수동 커밋을 푸시하면 reverse-sync가 실제 Git Diff를 분석해 기능 명세·API 계약·화면 명세에 변경점을 역으로 반영합니다.
  • SI 납품용 4대 산출물 패키지(SpecDeliverableAndGovernanceSupport): 확정된 스펙과 검증 결과를 바탕으로 프로그램 사양서(HTML), 화면 설계서(HTML), 테이블 명세서(CSV/XLSX), 단위 테스트 시나리오(CSV/XLSX)를 일괄 생성해 공공·금융 SI 검수 문서 작성 부담을 크게 줄입니다.

4. 벤더 독립성과 개발 거버넌스의 균형

SyncSDK와 5-Step Spec Studio 조합의 핵심은 AI에게 전권을 넘기는 것이 아니라, 교체 가능한 코딩 엔진, 명확한 사전 스펙 게이트, 사내 개발자 Co-Dev 리뷰, 최신 상태가 유지되는 산출물을 한 체계로 묶는 데 있습니다. 덕분에 팀은 최신 모델 발전 혜택을 즉시 수용하면서도 사내 아키텍처 표준과 감사 추적성을 흔들림 없이 지킬 수 있습니다.

SyncVerse 5-Step Spec Studio와 Co-Dev 흐름을 확인해 보세요 요구사항 정제부터 코딩 엔진 핫스왑, Monaco Diff 리뷰, SI 산출물 패키지 생성 화면을 공식 사이트에서 살펴볼 수 있습니다.

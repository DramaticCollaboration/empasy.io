4대 실무 장애물 원인 분석 및 SyncETA 해결 아키텍처 보기
이 글의 목차
  1. 1. 장애물 ① 금융·공공 보안 가상 키패드 입력
  2. 2. 장애물 ② 지연 등장하는 글로벌 쿠키 동의 팝업
  3. 3. 장애물 ③ 테스트 녹화·스크린샷 속 민감 개인정보 노출
  4. 4. 장애물 ④ 시나리오 밖의 404 하위 링크와 글자 겹침·화면 깨짐

1. 장애물 ① 금융·공공 보안 가상 키패드 입력

국내 금융·보험·공공 포털의 로그인·본인확인 화면은 키보드 후킹 방지를 위해 매 접속마다 숫자·문자 배열이 무작위로 재배치되는 이미지·캔버스 기반 보안 가상 키패드를 사용합니다. 일반적인 page.fill()이나 고정 좌표 클릭 스크립트는 이 단계에서 즉시 막히며, 해외 상용 테스트 도구 역시 국내 보안 키패드 패턴을 지원하지 못하는 경우가 많습니다.

SyncETA는 브라우저 동작 레코더와 실행 엔진에 보안 가상 키패드 자동 인식 입력 흐름을 기본 통합해, 매번 배열이 바뀌어도 대상 키 위치를 시각·DOM 맥락으로 식별하고 안전하게 로그인 단계를 통과합니다.

2. 장애물 ② 지연 등장하는 글로벌 쿠키 동의 팝업

유럽(GDPR), 미국(CCPA), 다국어 글로벌 브랜드 사이트는 페이지 로드 직후가 아니라 외부 CMP(Consent Management Platform) 스크립트가 로드된 뒤 2~5초 시점에 쿠키 동의 오버레이를 띄우는 경우가 흔합니다. 기존 방식처럼 goto 직후 고정 대기(sleep)를 두고 한 번만 닫기를 시도하면 두 가지 문제가 생깁니다.

  • 고정 대기 이후 늦게 뜬 모달이 다음 버튼 클릭을 가로막아 Element is obscured 실패 발생
  • 클릭이나 뒤로·앞으로 이동으로 새 문서에 진입했을 때 쿠키 검사가 누락되거나, 반대로 전역 플래그를 쓰면 다른 탭·시나리오까지 검사를 건너뛰는 부작용 발생

SyncETA 실행 엔진은 쿠키 모달 처리를 navigate 후처리가 아니라 공통 레코드 실행 진입점의 DOM 요소 탐색 직전으로 앞당겼습니다. 닫기 성공 이력은 전역 변수가 아닌 WeakSet<Page>으로 페이지 인스턴스별 격리 관리하고, 메인 프레임의 framenavigated 이벤트가 발생할 때만 해당 페이지 이력을 초기화합니다(iframe 내부 이동은 제외). 덕분에 지연 모달, 멀티 탭, 뒤로·앞으로 이동이 섞인 글로벌 사이트에서도 클릭 방해 없이 실행이 이어집니다.

3. 장애물 ③ 테스트 녹화·스크린샷 속 민감 개인정보 노출

E2E 테스트의 가장 큰 장점은 실패 순간의 스크린샷과 .webm 녹화 영상을 남겨 개발자에게 바로 공유할 수 있다는 점이지만, 실제 화면에 주민등록번호·전화번호·계좌번호·비밀번호가 찍히면 개인정보보호법 및 사내 보안 감사 위반 소지가 발생합니다.

SyncETA는 입력·캡처·LLM 요청 경계 전반에서 주민번호·전화번호 등 민감 개인정보를 자동으로 가림(마스킹) 처리하고, 외부 클라우드 연결이 금지된 금융·공공망을 위해 PC 로컬 데스크톱 앱 실행 및 사내 온프레미스 서버 + 로컬 LLM 구성을 공식 지원합니다.

4. 장애물 ④ 시나리오 밖의 404 하위 링크와 글자 겹침·화면 깨짐

핵심 결제 시나리오 20개가 모두 통과(Pass)했더라도, 프로모션 배너 링크 하나가 404를 반환하거나 다국어 번역 문구가 길어져 버튼 글자가 겹쳐 버리는 결함은 기존 기능 스크립트로 잡아낼 수 없습니다.

결함 유형 기존 스크립트 QA의 사각지대 SyncETA 시나리오 없는 전수 진단
하위 링크 오류 클릭 시나리오에 포함된 버튼만 확인 사이트 지식그래프로 페이지 내 하위 링크 404 및 링크 문구-도착 페이지 의미 불일치 전수 검사
레이아웃 · 디자인 깨짐 단순 픽셀 비교는 폰트·배너 변경에도 오탐 다발 글자 겹침, 빈 영역, 이미지·미디어 재생 오류를 시각·구조 기반으로 탐지
애매한 화면 판정 무조건 Pass 처리하거나 오탐 실패로 방치 확실한 항목만 정상 집계, 판단이 모호한 화면은 사진과 함께 [확인 필요]로 정직하게 분리

시나리오를 작성할 시간이 부족한 긴급 배포 직후에도 "하위 링크 검사해줘", "화면 깨짐 봐줘" 같은 한 줄 문장만으로 전수 진단을 실행하고, 검출된 문제는 버그 칸반에서 바로 추적·재검증할 수 있습니다.

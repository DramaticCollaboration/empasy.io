1. 현대 프론트엔드에서 정적 셀렉터가 깨지는 3가지 패턴

React, Vue 3, Tailwind CSS, CSS-in-JS가 표준이 된 환경에서 기존 CSS 선택자나 절대 XPath는 작은 UI 변경에도 쉽게 무력화됩니다.

  • 빌드 타임 해시 클래스 교체: .btn-submit_3kQ8z처럼 번들러(Vite, Webpack)가 생성한 클래스명이 다음 빌드에서 바뀌는 경우
  • 래퍼 컨테이너 삽입: 배너나 안내 문구 div가 하나 추가되면서 div:nth-child(3) > button 같은 위치 의존 XPath가 어긋나는 경우
  • 문구 및 배치 리뉴얼: 프로모션 개편으로 버튼 텍스트가 "구매하기"에서 "바로 결제"로 바뀌거나 우측 하단으로 이동하는 경우

2. 왜 "실패 시점 트리거 + 하이브리드 복구"로 설계했는가

처음부터 모든 클릭을 Vision-LLM에 맡기면 셀렉터는 깨지지 않지만, 회귀 테스트 1건에 수십 초가 걸리고 LLM 토큰 비용이 매번 청구됩니다. SyncETA는 정상 경로에서는 기존 Playwright 로케이터를 그대로 고속 재생하고, TimeoutError나 NoSuchElementError 또는 가림 현상이 발생했을 때만 Self-Healing 인터셉터가 개입하도록 분리했습니다.

3. Vision-LLM 좌표에서 DOM 노드를 역추적하는 4단계 파이프라인

STEP 01
실패 시점 컨텍스트 수집
현재 뷰포트 스크린샷(PNG), 접근성 트리(Accessibility Tree) 요약, 원본 동작 의도("결제하기 버튼 클릭")를 함께 묶어 수집합니다.
STEP 02
Vision-LLM 정규화 바운딩 박스 추론
비전 모델이 화면 문맥에서 목표 컴포넌트의 정규화 좌표 [ymin, xmin, ymax, xmax](0~1000 스케일)를 추론합니다.
STEP 03
CDP DOM.getNodeForLocation 노드 역추적
정규화 좌표의 중심점을 실제 뷰포트 CSS 픽셀로 환산해 Chrome DevTools Protocol로 활성 DOM 노드의 backendNodeId를 정확히 획득합니다.
STEP 04
대체 선택자 생성 · 고유성 검증 · 재개
추출된 노드에서 페이지 내 유일하게 매칭되고 상호작용 가능한(visible, enabled) 대체 선택자를 산출한 뒤 테스트를 이어갑니다.
// 정규화 좌표(0~1000) -> 뷰포트 CSS 픽셀 -> CDP 물리 DOM 노드 역추적 핵심 로직
const centerX = Math.round(((box.xmin + box.xmax) / 2000) * viewport.width);
const centerY = Math.round(((box.ymin + box.ymax) / 2000) * viewport.height);

const cdp = await page.context().newCDPSession(page);
const { backendNodeId } = await cdp.send('DOM.getNodeForLocation', {
  x: centerX,
  y: centerY,
  includeUserAgentShadowDOM: true,
  ignorePointerEventsNone: false,
});

4. 깨지기 어려운 대체 선택자를 고르는 4순위 규칙

단순히 좌표 클릭으로만 넘어가면 다음 실행 때 또 Vision-LLM을 호출해야 합니다. SyncETA는 역추적한 DOM 노드에서 다음 우선순위로 안정적인 선택자를 재생성해 자산화합니다.

우선순위 선택자 유형 생성 예시 선정 근거
1순위 테스트 전용 속성 [data-testid="submit-order"] 개발팀이 명시한 가장 안정적인 식별자
2순위 시맨틱 역할 · 접근성 라벨 role=button[name="결제하기"] 디자인·클래스 개편에도 비즈니스 역할 유지
3순위 인접 텍스트 앵커링 div:has-text("총 결제금액") >> button 화면 내 문맥적 상대 위치를 활용해 오매칭 방지
4순위 고유 구조 · 폼 속성 조합 form.order-form button[type="submit"] 해시 클래스 교체를 피하는 구조 기반 폴백

5. 거짓 양성(False Positive)을 막는 Human-in-the-Loop 승인 큐

자가 치유 기능에서 QA 엔지니어가 가장 경계하는 위험은 "결제 버튼이 실제로 사라진 장애인데 AI가 옆의 취소 버튼을 눌러 통과(Pass)로 처리해 버리는 사고"입니다. 이를 막기 위해 SyncETA는 다음 3중 안전장치를 적용합니다.

  • 위험도 분리 정책: 단순 클래스명 변경 같은 저위험 보정은 임시 실행 후 이력을 남기고, 버튼 의미·위치가 크게 바뀐 고위험 항목은 자동 확정하지 않고 [확인 필요] 및 자가 치유 제안 큐(Healing Queue)로 격리합니다.
  • Before/After 시각 대조: 이전 기준 스크린샷과 현재 대체 선택자가 가리키는 요소를 나란히 보여주고, 담당자가 1클릭으로 승인할 때만 기준 시나리오를 영구 갱신합니다.
  • 감사 이력 보관: 누가 언제 어떤 사유로 선택자 갱신을 승인했는지 감사 로그에 남겨 엔터프라이즈 QA 거버넌스를 충족합니다.

6. 내부 실증 평가 결과 요약

엠파시 엔지니어링 팀은 국내 이커머스 및 엔터프라이즈 포털 10개 사이트를 대상으로 6개월간 1,200회의 릴리즈 회귀 테스트에서 본 알고리즘을 평가했습니다(연구 아카이브 원문 기준).

  • 식별자 파손 복구율: 식별자 파손 342건 중 318건(93.0%)을 수동 코드 수정 없이 대체 선택자로 자동 보정해 실행을 완료했습니다.
  • 평균 치유 소요 시간: 스냅샷 캡처부터 바운딩 박스 추론·CDP 노드 확정·실행 재개까지 평균 1.2초가 소요되었습니다.
  • 유지보수 공수 변화: 동일 테스트 스위트의 릴리즈별 셀렉터 수동 갱신 작업 시간이 평균 78.4% 감소했습니다. (실제 도입 조직별 절감율은 운영 사이트 1곳 대상 2~4주 시범 적용으로 직접 계측합니다.)

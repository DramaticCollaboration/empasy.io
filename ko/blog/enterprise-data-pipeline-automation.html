2026-01-10 (업데이트 2026-11-23) • 읽는 시간 약 6분 • 데이터 정리 · 보안 파이프라인

보안이 중요한 기업 환경에서의 비정형 업무 데이터 정리 자동화 사례

경영진 · 현업 담당자를 위한 3줄 요약
  • 기존 문제사내 곳곳에 쌓인 문서·게시물·외부 자료를 사람이 일일이 분류하고 개인정보를 가려 정리하는 데 많은 시간과 보안 부담이 듭니다.
  • 해결 방식민감 개인정보를 자동으로 가림 처리하면서 비정형 문서를 구조화해 3중 하이브리드 검색(pgvector + BM25 + 지식 그래프)에 바로 쓰기 좋게 정리합니다.
  • 기대 효과사내 보안 규정과 부서별 접근 권한을 지키면서도 사내 지식 검색 정확도와 보고서 작성 속도를 함께 높입니다.

금융·공공·제조 등 보안 규제가 엄격한 기업 현장에는 PDF 지침서, 회의록, 사내 게시판, 협력사 안내문, 외부 법령·시장 공시 자료 등 막대한 양의 비정형 업무 데이터가 매일 쌓입니다. 그러나 원문 파일이 폴더와 게시판에 흩어져 있으면 필요한 근거를 찾는 데만 수 시간이 걸리고, 생성형 AI 검색(RAG)에 그대로 연결하려 해도 개인정보(PII) 유출 위험과 문서 노이즈 때문에 도입이 멈추는 경우가 많습니다.

엠파시는 SyncCrawl(외부·내부 수집 정제), SyncLLM(개인정보 가림·정책 통제), sync-module-rag(3중 하이브리드 색인), SyncInsight(권한 기반 조회)를 결합해 보안 경계 안에서 비정형 데이터를 안전하게 구조화하는 5단계 파이프라인을 구축했습니다.

1. 비정형 데이터 자동화에서 자주 막히는 3가지 병목

  • 원문 내 민감정보 혼재: 공문서나 민원·상담 이력 안에 주민등록번호, 휴대전화 번호, 계좌번호, 이메일, 고객명이 비정형 텍스트 형태로 섞여 있어 단순 일괄 색인 시 보안 규정 위반 소지가 큽니다.
  • 레이아웃·노이즈로 인한 검색 품질 저하: 웹 페이지의 광고·메뉴, PDF의 머리글·바닥글, 깨진 표 구조가 그대로 임베딩되면 AI가 무관한 문장을 인용하거나 수치를 오독합니다.
  • 권한 미분리와 최신성 누락: 부서별 열람 등급을 구분하지 않고 단일 벡터 DB에 적재하거나, 개정된 규정 문서를 재색인하지 못해 과거 기준이 노출되는 문제가 발생합니다.

2. 5-Layer 보안 중심 데이터 정리 파이프라인

SyncSeries는 원본 수집부터 권한 기반 검색까지 모든 단계에 검증·마스킹·감사 이력을 내장한 5계층 아키텍처로 비정형 데이터를 처리합니다.

LAYER 01
안전 수집 및 변경 감지
SyncCrawl이 robots.txt 준수 하에 공개 웹과 사내 문서를 수집하고 해시 비교로 변경 문서만 선별
LAYER 02
8대 개인정보(PII) 자동 가림
주민번호·연락처·계좌·카드·이메일·사업자번호 등 민감 패턴을 색인 전 단계에서 탐지·마스킹
LAYER 03
구조화 및 노이즈 정제
메뉴·광고·반복 머리글을 제거하고 제목(H1~H4)·표·목록 계층을 보존한 Clean Markdown/JSON 생성
LAYER 04
3중 하이브리드 RAG 색인
sync-module-rag가 문맥 단위 청킹 후 PostgreSQL 18.6 pgvector + BM25 + 지식 그래프로 통합 색인
LAYER 05
권한 통제 조회 및 승인
부서·직급 RBAC 필터와 감사 로그 하에 SyncInsight로 근거 출처 포함 답변·보고서 제공

3. 개인정보 보호 및 폐쇄망 보안 설계 원칙

민감한 업무 문서를 다루는 기업 환경에서는 검색 성능보다 데이터 주권과 추적 가능성이 먼저 보장되어야 합니다.

  • 색인 전 선제 마스킹(Pre-Index Masking): 텍스트가 임베딩 모델이나 외부 API로 넘어가기 전에 정규식 규칙과 문맥 검증을 결합해 민감 식별자를 토큰(예: [MASKED_PHONE])으로 치환합니다.
  • 사내망 내재화 옵션: 외부 통신이 차단된 환경에서는 사내 서버에 배치된 로컬 임베딩·LLM 런타임(vLLM, Ollama)과 PostgreSQL 18.6 pgvector만으로 전체 파이프라인을 완결합니다.
  • 부서별 권한 태그 및 출처 역추적: 모든 청크(Chunk)에 문서 등급·부서 권한·버전·원본 URL 메타데이터를 함께 저장해, 조회 시 인가된 사용자에게만 근거 문장과 함께 노출합니다.

4. 실무 적용 효과 및 단계적 도입 가이드

  • 수작업 분류·비식별화 공수 절감: 문서 취합, 중복 제거, 개인정보 가림 처리, 요약 정리 과정을 자동 파이프라인으로 전환해 담당자는 예외 건 검토와 최종 승인에만 집중할 수 있습니다.
  • 검색 정확도와 감사 대응력 향상: 표·제목 구조가 보존된 정제 문서와 3중 하이브리드 검색을 결합해, 단순 키워드 검색이나 순수 벡터 검색 대비 근거 적중률과 응답 일관성을 높입니다.
  • 소규모 파일럿 권장: 전사 문서를 한 번에 연결하기보다, 사내 규정집·FAQ·공개 법령처럼 활용 빈도가 높은 1~2개 문서군으로 1~2주 파일럿을 진행해 마스킹 규칙과 검색 품질을 검증한 뒤 단계적으로 확장하는 방식을 권장합니다.
사내 문서와 외부 공개 정보를 안전하게 검색 자산으로 전환해 보세요 SyncCrawl, SyncLLM, SyncInsight가 폐쇄망 환경에서 비정형 데이터를 어떻게 정제·검색하는지 확인할 수 있습니다.
